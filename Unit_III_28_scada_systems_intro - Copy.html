Chapter 28: Supervisory Control and Data Acquisition (SCADA) Systems

This chapter introduces the architecture, operational framework, and telemetry mechanics of SCADA systems. Topics include Master Terminal Units (MTU), Remote Terminal Units (RTU), Human-Machine Interfaces (HMI), polling cycle dynamics, and industrial network bandwidth analysis.

1. SCADA System Hierarchy & Core Hardware Elements

Hardware Reference & Functional Overview


Level 1 to Level 3 Automation Hierarchy

A SCADA system provides high-level supervisory monitoring and centralized control across geographically dispersed industrial assets. Its four-tier hierarchy comprises:

  • Field Instrumentation (Level 0): Sensors, transducers, and control actuators physically connected to processes.
  • Remote Terminal Units & PLCs (Level 1): Field-level controllers executing localized closed-loop control algorithms.
  • Master Terminal Unit / SCADA Server (Level 2): Centralized control software collecting field data, logging alarms, and executing supervisory commands.
  • HMI Workstations & Enterprise Historians (Level 3): Graphical monitoring consoles for human operators and long-term databases.

The system update delay across telemetric channels is governed by the total response cycle:

$$T_{response} = T_{poll} + T_{rtu\_proc} + T_{comm\_latency} + T_{mtu\_update}$$

2. Architectural Differences: SCADA, DCS, and PLC Systems

Supervisory Control vs. Localized Automation

Industrial facilities utilize distinct automation platforms depending on spatial coverage, control latency, and processing requirements:

  • PLC (Programmable Logic Controller): Microsecond-level real-time discrete control optimized for local machinery and automated cells.
  • DCS (Distributed Control System): Process-driven architecture with tightly integrated controllers deployed across a single localized plant (e.g., oil refinery).
  • SCADA (Supervisory Control and Data Acquisition): Event-driven supervisory architecture spanning large geographical areas (e.g., electrical grids, pipeline networks) connected via long-distance telemetry.

Numerical Problems: Telemetry Polling Cycles & Bandwidth Computation

Problem 1: Master Terminal Unit Polling Cycle Duration

Scenario: A regional water distribution SCADA master station polls $N = 48\text{ Remote Terminal Units (RTUs)}$ over a serial RS-485 telemetry network operating at a baud rate of $9600\text{ bits/second}$. Each RTU polling sequence consists of:

  • Master Request Packet: $12\text{ bytes}$
  • RTU Data Response Packet: $64\text{ bytes}$
  • RTU Processing & Transceiver Turnaround Time: $T_{turn} = 15\text{ ms per node}$

Assuming 1 start bit, 8 data bits, and 1 stop bit (10 bits per byte framing), calculate:

  1. The time required to transmit one request-response frame $T_{frame}$ for a single RTU in milliseconds.
  2. The total system polling sweep cycle time $T_{sweep}$ for all 48 RTUs.
  3. The maximum update frequency $f_{update}$ for any single field sensor in Hertz ($\text{Hz}$).

Step-by-Step Solution:

1. Compute Single Frame Transmission Time ($T_{frame}$):

$$\text{Total Bytes per Cycle} = 12\text{ bytes (Request)} + 64\text{ bytes (Response)} = 76\text{ bytes}$$
$$\text{Total Bits per Cycle} = 76\text{ bytes} \times 10\text{ bits/byte} = 760\text{ bits}$$
$$T_{comm} = \frac{760\text{ bits}}{9600\text{ bps}} = 0.079167\text{ seconds} = 79.17\text{ ms}$$
$$T_{frame} = T_{comm} + T_{turn} = 79.17\text{ ms} + 15.0\text{ ms} = 94.17\text{ ms per RTU}$$

2. Compute Total Master Sweep Time ($T_{sweep}$):

$$T_{sweep} = N \times T_{frame} = 48 \times 94.17\text{ ms} = 4520.16\text{ ms} \approx 4.52\text{ seconds}$$

3. Compute Maximum Update Frequency ($f_{update}$):

$$f_{update} = \frac{1}{T_{sweep}} = \frac{1}{4.52016\text{ s}} \approx 0.221\text{ Hz}$$

Problem 2: Report-by-Exception (RBE) Bandwidth Efficiency

Scenario: To improve update times, the SCADA system is upgraded to a Report-by-Exception (RBE) protocol (such as DNP3 or MQTT). Under normal operating conditions, only $10\%$ of the RTUs report changed data during any 1-second interval. The RBE event packet size is $32\text{ bytes}$.

Calculate:

  1. The average required network data rate in bits per second ($\text{bps}$) under RBE operation.
  2. The percentage reduction in bandwidth utilization compared to the continuous polling scheme from Problem 1.

Step-by-Step Solution:

1. Calculate Average Data Rate under RBE:

$$\text{Reporting RTUs per second} = 48 \times 0.10 = 4.8\text{ nodes/second}$$
$$\text{Data Transfer Rate} = 4.8\text{ nodes/s} \times 32\text{ bytes/node} \times 10\text{ bits/byte} = 1536\text{ bps}$$

2. Compute Bandwidth Reduction Percentage:

$$\text{Continuous Polling Data Rate} = \frac{48 \times 760\text{ bits}}{4.52\text{ s}} \approx 8070.8\text{ bps}$$
$$\text{Bandwidth Reduction} = \left(1 - \frac{1536\text{ bps}}{8070.8\text{ bps}}\right) \times 100\% = (1 - 0.1903) \times 100\% \approx 80.97\%$$
