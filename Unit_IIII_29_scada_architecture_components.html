Subsystem Functional Breakdowns

A production SCADA system relies on distinct, interconnected processing tiers designed for reliability and zero-downtime operation:

  • Master Terminal Unit (MTU / SCADA Server): The core supervisory engine. Runs polling schedulers, handles alarm state logic, executes control scripts, and serves data to client nodes. Usually configured as a dual-redundant hot-standby pair.
  • Remote Terminal Unit (RTU): Ruggedized field microcomputers with wide operating temperature ranges, backup battery UPS systems, onboard signal conditioning, and local RTC timers for precise time-stamping ($1\text{ ms}$ resolution).
  • Process Historian: High-performance, time-series relational or columnar database optimized for high-speed ingestion and long-term storage of process tag values.
  • Human-Machine Interface (HMI): Graphical client stations that convert raw database tags into real-time visual process graphics, trend charts, and operator alarm panels.

Numerical Problems: Historian Storage & Redundancy Failover Sizing

Problem 1: Process Historian Data Storage & Compression Sizing

Scenario: A regional oil refinery SCADA historian monitors $N = 25,000\text{ process tags}$. Each record contains:

  • Tag Identifier: $4\text{ bytes}$
  • IEEE 754 Floating Point Value: $4\text{ bytes}$
  • UNIX Timestamp ($1\text{ ms}$ precision): $8\text{ bytes}$
  • Quality Flag / Status Field: $2\text{ bytes}$

Data is polled continuously at a sampling rate of 1 sample per second ($1\text{ Hz}$) per tag. The historian uses a deadband compression algorithm that successfully reduces stored records by $75\%$ ($25\%$ storage retention).

Calculate:

  1. The uncompressed raw data ingestion rate in Megabytes per second ($\text{MB/s}$).
  2. The actual compressed data storage required per day in Gigabytes ($\text{GB/day}$).
  3. The total storage capacity required in Terabytes ($\text{TB}$) to retain process data for 5 years.

Step-by-Step Solution:

1. Calculate Record Size and Raw Data Ingestion Rate:

$$\text{Record Size} = 4\text{ (ID)} + 4\text{ (Value)} + 8\text{ (Timestamp)} + 2\text{ (Status)} = 18\text{ bytes/sample}$$
$$\text{Raw Ingestion Rate} = 25,000\text{ tags} \times 18\text{ bytes/sample} \times 1\text{ sample/s} = 450,000\text{ bytes/s}$$
$$\text{Raw Data Rate in MB/s} = \frac{450,000\text{ B/s}}{1,000,000\text{ B/MB}} = 0.45\text{ MB/s}$$

2. Compute Daily Compressed Storage Volume:

$$\text{Raw Volume per Day} = 0.45\text{ MB/s} \times 86,400\text{ seconds/day} = 38,880\text{ MB/day} = 38.88\text{ GB/day}$$
$$\text{Compressed Volume per Day} = 38.88\text{ GB/day} \times (1 - 0.75) = 38.88 \times 0.25 = 9.72\text{ GB/day}$$

3. Compute 5-Year Storage Capacity Requirement:

$$\text{Total Storage (5 Years)} = 9.72\text{ GB/day} \times (365 \times 5\text{ days}) = 9.72 \times 1825 = 17,739\text{ GB}$$
$$\text{Total Storage in Terabytes} = \frac{17,739\text{ GB}}{1,000\text{ GB/TB}} \approx 17.74\text{ TB}$$

Problem 2: Dual Hot-Standby MTU Availability Calculation

Scenario: A SCADA system uses two identical MTU servers in a parallel redundant configuration. The Mean Time Between Failures (MTBF) for a single server is $\text{MTBF} = 10,000\text{ hours}$, and the Mean Time To Repair (MTTR) is $\text{MTTR} = 10\text{ hours}$.

Calculate:

  1. The operational availability $A_s$ of a single non-redundant MTU server.
  2. The total system availability $A_{sys}$ of the dual hot-standby pair.
  3. The expected total annual downtime in minutes for the redundant system.

Step-by-Step Solution:

1. Calculate Single Server Availability ($A_s$):

$$A_s = \frac{\text{MTBF}}{\text{MTBF} + \text{MTTR}} = \frac{10,000}{10,000 + 10} = \frac{10,000}{10,010} \approx 0.999001\quad (99.9001\%)$$

2. Compute Redundant System Availability ($A_{sys}$):

For a parallel configuration where at least one server must operate, the system unreliability $U_{sys}$ is the product of individual unavailabilities ($U_s = 1 - A_s$):

$$U_s = 1 - 0.999001 = 0.000999$$
$$U_{sys} = U_s^2 = (0.000999)^2 \approx 0.000000998$$
$$A_{sys} = 1 - U_{sys} = 1 - 0.000000998 = 0.999999002\quad (99.9999\%)$$

3. Compute Expected Annual System Downtime:

$$\text{Annual Hours} = 365 \times 24 = 8,760\text{ hours}$$
$$\text{Downtime Hours} = 8,760\text{ h} \times U_{sys} = 8,760 \times 0.000000998 \approx 0.008742\text{ hours}$$
$$\text{Downtime in Minutes} = 0.008742\text{ hours} \times 60\text{ min/hour} \approx 0.525\text{ minutes/year}\quad (\approx 31.5\text{ seconds/year})$$
