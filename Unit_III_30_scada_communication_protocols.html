Industrial Networking Paradigms

Field networks translate real-world process variables into digital packet streams across three distinct protocol generations:

  • Modbus (RTU / TCP): Open master-slave protocol using 16-bit registers. Simple, ubiquitous, but lacks native timestamping or object modeling.
  • PROFIBUS (DP / PA): Token-ring multi-master, master-slave protocol operating over RS-485 (DP) or Manchester Bus Powered (PA) physical layers up to $12\text{ Mbps}$.
  • EtherNet/IP: Modern industrial Ethernet protocol utilizing CIP (Common Industrial Protocol) over standard TCP/IP and UDP transport layers for producer/consumer data exchange.

Numerical Problems: Protocol Overhead & Line Throughput Sizing

Problem 1: Modbus RTU vs. Modbus TCP Protocol Overhead & Transfer Time

Scenario: A SCADA master needs to read $N = 50\text{ Holding Registers}$ ($100\text{ bytes}$ of data) from a remote PLC using Function Code 03 (Read Holding Registers).

Compare the transmission time for:

  1. Modbus RTU: Operating at $19,200\text{ baud}$, 11 bits per byte framing (1 start, 8 data, 1 parity, 1 stop). Include the required 3.5 character silent interval ($t_{3.5}$) before and after the message.
  2. Modbus TCP: Operating over a $100\text{ Mbps}$ Switched Ethernet link. Frame overhead comprises: MBAP Header ($7\text{ bytes}$), TCP Header ($20\text{ bytes}$), IP Header ($20\text{ bytes}$), and Ethernet Frame Header/Trailer ($26\text{ bytes}$).

Step-by-Step Solution:

1. Compute Modbus RTU Transmission Time:

$$\text{RTU Request Packet Size} = 1\text{ (ID)} + 1\text{ (Func)} + 2\text{ (Addr)} + 2\text{ (Count)} + 2\text{ (CRC)} = 8\text{ bytes}$$
$$\text{RTU Response Packet Size} = 1\text{ (ID)} + 1\text{ (Func)} + 1\text{ (Byte Count)} + 100\text{ (Data)} + 2\text{ (CRC)} = 105\text{ bytes}$$
$$\text{Total RTU Bytes} = 8 + 105 = 113\text{ bytes}$$
$$t_{3.5} = \frac{3.5 \times 11\text{ bits}}{19,200\text{ bps}} \approx 2.005\text{ ms}$$
$$T_{RTU\_comm} = \frac{113\text{ bytes} \times 11\text{ bits/byte}}{19,200\text{ bps}} = \frac{1243\text{ bits}}{19,200\text{ bps}} \approx 64.74\text{ ms}$$
$$T_{RTU\_total} = T_{RTU\_comm} + (2 \times t_{3.5}) = 64.74\text{ ms} + 4.01\text{ ms} = 68.75\text{ ms}$$

2. Compute Modbus TCP Transmission Time:

$$\text{Modbus TCP Overhead} = 26\text{ (Eth)} + 20\text{ (IP)} + 20\text{ (TCP)} + 7\text{ (MBAP)} = 73\text{ bytes overhead}$$
$$\text{TCP Request Data} = 2\text{ bytes (PDU)} \implies \text{Total Request Size} = 73 + 2 = 75\text{ bytes}$$
$$\text{TCP Response Data} = 2\text{ (Func/Byte Count)} + 100\text{ (Data)} = 102\text{ bytes} \implies \text{Total Response Size} = 73 + 102 = 175\text{ bytes}$$
$$\text{Total TCP Bytes} = 75 + 175 = 250\text{ bytes} = 2000\text{ bits}$$
$$T_{TCP} = \frac{2000\text{ bits}}{100,000,000\text{ bps}} = 0.000020\text{ seconds} = 0.020\text{ ms}\quad (20\ \mu\text{s})$$

Problem 2: PROFIBUS DP Bus Cycle Time Sizing

Scenario: A PROFIBUS DP network operates at a baud rate of $1.5\text{ Mbps}$ connecting 1 Class-1 Master to $N = 16\text{ Slave Devices}$. Each slave exchanges an 11-byte telegram (6-byte header + 5-byte I/O data). PROFIBUS uses 11-bit UART framing per byte.

Calculate:

  1. The raw message transmission time $T_{msg}$ per slave node.
  2. The total bus cycle time $T_{cycle}$ assuming a station delay $T_{slot} = 15\ \mu\text{s}$ per node.

Step-by-Step Solution:

1. Calculate Transmission Time per Slave ($T_{msg}$):

$$\text{Frame Bytes per Node (Req + Resp)} = 11\text{ bytes (Req)} + 11\text{ bytes (Resp)} = 22\text{ bytes}$$
$$\text{Bits per Node} = 22\text{ bytes} \times 11\text{ bits/byte} = 242\text{ bits}$$
$$T_{msg} = \frac{242\text{ bits}}{1,500,000\text{ bps}} = 1.6133 \times 10^{-4}\text{ seconds} = 161.33\ \mu\text{s}$$

2. Compute Total Bus Cycle Time ($T_{cycle}$):

$$T_{node} = T_{msg} + T_{slot} = 161.33\ \mu\text{s} + 15.0\ \mu\text{s} = 176.33\ \mu\text{s}$$
$$T_{cycle} = N \times T_{node} = 16 \times 176.33\ \mu\text{s} = 2821.28\ \mu\text{s} \approx 2.82\text{ ms}$$
