HMI Hardware & Operational Overview


Core Functional Responsibilities

An HMI serves as the localized visual bridge between human operators and field automation devices (PLCs/PACs):

  • Process Visualization: Dynamic 2D/3D graphical mapping of process states, tank levels, valve positions, and motor status.
  • Control Setpoint Entry: Secure manual intervention allowing operators to write setpoints, start/stop sequences, and change modes.
  • Alarm Management: Real-time event logging, visual annunciation, and alarm priority filtering per ANSI/ISA-18.2 standards.

Numerical Problems: Screen Refresh Latency & Bandwidth Sizing

Problem 1: HMI Screen Tag Polling Latency and Bandwidth Requirement

Scenario: An operator switches to an HMI process screen displaying $N = 240$ active tags mapped to a field PLC. Among these tags:

  • 160 tags are 32-bit Floating Point values ($4\text{ bytes}$ each).
  • 80 tags are Boolean status flags packaged into 16-bit Integer words ($2\text{ bytes}$ each, $10\text{ words total} = 20\text{ bytes}$).

The HMI terminal polls data using EtherNet/IP explicit messaging. Each read request header incurs an overhead of $56\text{ bytes}$, and the PLC response frame overhead is $64\text{ bytes}$. The screen update rate is set to $R = 4\text{ updates/second}\ (250\text{ ms cycle})$.

Calculate:

  1. The total data payload size per poll in bytes.
  2. The net network bandwidth consumed by this single HMI screen in kilobits per second ($\text{kbps}$).
  3. The total time required to transfer one full screen update over a $10\text{ Mbps}$ ethernet connection.

Step-by-Step Solution:

1. Compute Total Payload and Frame Sizes:

$$\text{Data Payload} = (160\text{ tags} \times 4\text{ bytes}) + 20\text{ bytes} = 640 + 20 = 660\text{ bytes}$$
$$\text{Total Frame Size} = 660\text{ (Data)} + 56\text{ (Req Header)} + 64\text{ (Resp Header)} = 780\text{ bytes/poll}$$

2. Calculate Network Bandwidth Consumption:

$$\text{Data Rate} = 780\text{ bytes/poll} \times 8\text{ bits/byte} \times 4\text{ polls/second} = 24,960\text{ bits/second}$$
$$\text{Bandwidth in kbps} = \frac{24,960}{1000} = 24.96\text{ kbps}$$

3. Calculate Transfer Time per Screen Update:

$$\text{Total Bits per Poll} = 780 \times 8 = 6240\text{ bits}$$
$$T_{transfer} = \frac{6240\text{ bits}}{10,000,000\text{ bits/sec}} = 0.000624\text{ seconds} = 0.624\text{ ms}$$

Problem 2: HMI Alarm Processing Capacity and Response Latency

Scenario: During a plant trip, an HMI receives a burst of $N_a = 150$ alarms within a 1-second interval. The HMI event processor logs each alarm to an onboard SQLite database (taking $t_{db} = 2.5\text{ ms}$ per write) and renders the updated alarm list on screen (taking $t_{render} = 15\text{ ms}$ per batch update of up to 50 alarms).

Calculate:

  1. The total time required to log all 150 incoming alarms to the database.
  2. The total screen rendering latency for processing the full 150-alarm burst.
  3. The total worst-case time elapsed before the final alarm is displayed to the operator.

Step-by-Step Solution:

1. Compute Total Database Ingestion Time:

$$T_{db} = 150\text{ alarms} \times 2.5\text{ ms/alarm} = 375.0\text{ ms}$$

2. Compute Total Render Latency:

$$\text{Render Batches} = \left\lceil \frac{150}{50} \right\rceil = 3\text{ batches}$$
$$T_{render} = 3\text{ batches} \times 15\text{ ms/batch} = 45.0\text{ ms}$$

3. Calculate Total Alarm Processing Latency:

$$T_{total} = T_{db} + T_{render} = 375.0\text{ ms} + 45.0\text{ ms} = 420.0\text{ ms}$$
