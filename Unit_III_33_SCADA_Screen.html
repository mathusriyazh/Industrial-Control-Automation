Chapter 33: Designing Simple SCADA Screens

This chapter covers the fundamentals of designing Human-Machine Interfaces (HMI) and Supervisory Control and Data Acquisition (SCADA) screens. Topics include visual layout principles (ISA-101 standards), tag binding architecture, alarm state representations, refresh update cycles, and network bandwidth budgeting.

Core Design Guidelines (ISA-101)

Modern industrial SCADA screens prioritize situational awareness over complex 3D graphics:

  • High-Performance Color Palette: Neutral gray backgrounds reduce operator eye fatigue and maximize visual contrast for abnormal states.
  • Color Usage for Status: Bright colors (Red, Amber) are strictly reserved for alarms and exceptions, avoiding static visual clutter.
  • Direct Tag Mapping: Graphic widgets bind to OPC UA or Modbus tags in real time using deadband filters to reduce unnecessary updates.

Numerical Problems: Telemetry Throughput & Refresh Budgeting

Problem 1: SCADA Tag Database Bandwidth Consumption

Scenario: A SCADA server polls an industrial site with $N = 2,500$ operational tags over an OPC UA network interface. The tag breakdown is as follows:

  • $60\%$ Digital Status Tags (1-bit booleans, packed into 1 byte with metadata = 4 bytes/tag).
  • $40\%$ Analog Process Values (32-bit floating-point numbers + status metadata = 12 bytes/tag).

The screen updates require $50\%$ of tags to be polled continuously at $f_{fast} = 4\text{ Hz}$ ($250\text{ ms}$ rate) and the remaining $50\%$ to be polled at $f_{slow} = 1\text{ Hz}$ ($1000\text{ ms}$ rate).

Calculate:

  1. The average size per tag (in bytes) across the tag database.
  2. The raw polling telemetry throughput required in kilobytes per second ($\text{KB/s}$) and kilobits per second ($\text{Kbps}$).
  3. The total data transferred during an 8-hour operator shift in megabytes ($\text{MB}$).

Step-by-Step Solution:

1. Compute Average Tag Size ($S_{avg}$):

$$S_{avg} = (0.60 \times 4\text{ bytes}) + (0.40 \times 12\text{ bytes}) = 2.4 + 4.8 = 7.2\text{ bytes/tag}$$

2. Compute Total Polling Data Rate:

$$\text{Fast Tags Polling Rate} = 1,250\text{ tags} \times 4\text{ updates/sec} = 5,000\text{ tag-updates/sec}$$
$$\text{Slow Tags Polling Rate} = 1,250\text{ tags} \times 1\text{ update/sec} = 1,250\text{ tag-updates/sec}$$
$$\text{Total Updates} = 5,000 + 1,250 = 6,250\text{ updates/sec}$$
$$\text{Data Throughput (KB/s)} = \frac{6,250\text{ updates/sec} \times 7.2\text{ bytes}}{1,000} = 45.0\text{ KB/s}$$
$$\text{Data Throughput (Kbps)} = 45.0\text{ KB/s} \times 8 = 360.0\text{ Kbps}$$

3. Compute Shift Telemetry Transfer Volume:

$$\text{Shift Duration} = 8\text{ hours} \times 3,600\text{ seconds} = 28,800\text{ seconds}$$
$$\text{Total Shift Storage} = \frac{45.0\text{ KB/s} \times 28,800\text{ s}}{1,024} \approx 1,265.625\text{ MB} \approx 1.266\text{ GB}$$

Problem 2: Screen Rendering and Display Refresh Latency

Scenario: An HMI client screen displays $N_{screen} = 180$ dynamic UI widgets (gauges, digital readouts, trends). To ensure a smooth user interface, the screen must refresh at $f_{render} = 10\text{ Hz}$ ($T_{frame} = 100\text{ ms}$). The latency components per cycle are:

  • Network Request/Response Round-Trip Time (RTT): $t_{net} = 32\text{ ms}$
  • OPC Server Data Serialization Time: $t_{serial} = 18\text{ ms}$
  • Graphic Widget Redraw Execution Time per widget: $t_{widget} = 0.15\text{ ms/widget}$

Calculate:

  1. The total rendering duration $t_{render}$ required to redraw all screen widgets.
  2. The available idle buffer time before violating the $100\text{ ms}$ frame deadline.
  3. The maximum number of dynamic widgets ($N_{max}$) the screen can support without exceeding $T_{frame}$.

Step-by-Step Solution:

1. Compute Total Screen Widget Rendering Time ($t_{render}$):

$$t_{render} = 180\text{ widgets} \times 0.15\text{ ms/widget} = 27.0\text{ ms}$$

2. Compute Total Frame Delay and Remaining Idle Time:

$$t_{total\_frame} = t_{net} + t_{serial} + t_{render} = 32\text{ ms} + 18\text{ ms} + 27\text{ ms} = 77.0\text{ ms}$$
$$t_{idle} = T_{frame} - t_{total\_frame} = 100\text{ ms} - 77.0\text{ ms} = 23.0\text{ ms}$$

3. Compute Maximum Supported Dynamic Widgets ($N_{max}$):

$$t_{render\_max} = T_{frame} - (t_{net} + t_{serial}) = 100\text{ ms} - 50\text{ ms} = 50.0\text{ ms}$$
$$N_{max} = \lfloor \frac{50.0\text{ ms}}{0.15\text{ ms/widget}} \rfloor = \lfloor 333.33 \rfloor = 333\text{ widgets}$$
